# ลพบุรี · เมืองสามยุค

Landing page แนะนำ 10 แหล่งท่องเที่ยวประวัติศาสตร์จังหวัดลพบุรี สร้างด้วย **Tailwind CSS** เป็นแกนหลัก
UI แบบ bento โทนครีม–ส้มดินเผา (การ์ดตั๋ว, วิดเจ็ตสภาพอากาศสด, แผนที่แตะได้, เมนูซ้าย/ล่าง) พร้อมไดโอรามาและโมเดลอาคาร 3 มิติด้วย **Three.js** (ลากหมุนได้, มีแสงเงา) และตัวสำรอง CSS 3D เมื่อไม่มี WebGL, เส้นทางเดินเมืองเก่า, ลิงก์วิดีโอ YouTube, แหล่งอ้างอิง และสมุดเยี่ยม

## รันบนเครื่อง

```bash
npm install
npm run build      # Tailwind -> assets/tailwind.css และ bundle Three.js (src/three-scenes.js) -> assets/js/three-scenes.js
                   # ไฟล์ที่ build แล้วถูก commit ไว้ เปิดผ่าน server ได้เลย
npm start          # เสิร์ฟหน้าเว็บ + API สมุดเยี่ยม ที่ http://localhost:3000
```

## เผยแพร่ด้วย GitHub Pages

`.github/workflows/pages.yml` build (`npm ci && npm run build`) แล้วเผยแพร่เฉพาะ `index.html` + `assets/` (ราว 17 MB, 27 ไฟล์ — ไม่รวม `source-models/` ไฟล์ต้นฉบับโมเดลขนาดใหญ่ `src/` `tools/` `i18n/` และไฟล์สำรอง `file://`) ทุกครั้งที่ push เข้า `main` หรือสั่งเองจากแท็บ Actions ผลคือเว็บอยู่ที่ `https://<ผู้ใช้>.github.io/<ชื่อ repo>/` เป็น HTTPS จึงใช้ AR บนมือถือได้

ตั้งค่าครั้งเดียว (ทำได้เฉพาะเจ้าของ repo):
1. **Settings → Pages → Build and deployment → Source = GitHub Actions**
2. repo แบบ **private** ต้องใช้แผนเสียเงิน (GitHub Pro/Team) ถึงจะเปิด Pages ได้ แผนฟรีต้องเปลี่ยน repo เป็น public (Settings → General → Danger Zone → Change visibility) — ก่อนเปลี่ยนให้พิจารณาว่าประวัติ git มีไฟล์ต้นฉบับโมเดล/ภาพ (`source-models/`) ซึ่งจะเปิดเผยตามไปด้วย
3. merge เข้า `main` แล้วดูผลที่แท็บ Actions → "Deploy to GitHub Pages" (หรือกด Run workflow)

ข้อจำกัดของ Pages: ไม่มีเซิร์ฟเวอร์ สมุดเยี่ยมจึงเก็บในเบราว์เซอร์ของผู้ชมแต่ละคนเท่านั้น (ไม่แชร์ร่วมกัน) ถ้าต้องการสมุดเยี่ยมร่วมกัน ให้รัน `server.js` บนโฮสต์ที่มี Node (เช่น Render/Fly/VPS) แล้วชี้ `API` ใน `assets/js/app.js` ไปที่โฮสต์นั้น (ต้องเปิด CORS) ถ้าใช้โดเมนของตัวเอง ให้แก้ URL ใน `og:url`, `og:image`, `canonical` ของ `index.html` และรูปแชร์ลิงก์ `assets/img/og-cover.jpg` (1200×630)

## ปรับตำแหน่งหมุดบนแผนที่ 3 มิติ

พิกัดหมุดอยู่ที่ `PROVINCE_MODEL.hotspots` ใน `assets/js/data.js` (หน่วยของไฟล์โมเดล กึ่งกลาง ≈ 0,0) หมุดของปรางค์แขก วัดนครโกษา และวัดเสาธงทองเป็นตำแหน่งที่ประมาณจากทิศทางจริงเทียบกับหมุดอื่น เพราะในโมเดลแผนที่ไม่มีอาคารเฉพาะของสามแห่งนี้ ถ้าต้องการขยับ ให้รัน `npm start` แล้วเปิด `/map-debug.html` (มุมมองจากด้านบน มีตารางพิกัดและหมุดทุกจุด) อ่านพิกัดจากตารางแล้วแก้ค่า x, z ใน `data.js` (ไฟล์ `map-debug.html` ใช้ตอนพัฒนา ไม่ถูกเผยแพร่)

## หน้าแยกของแต่ละสถานที่

หน้าแรกแสดงการ์ดสรุป กดแล้วไปที่หน้าของสถานที่นั้น (`places/<id>.html`) ซึ่งมีภาพถ่าย ประวัติ สถาปัตยกรรม ไฮไลต์ เตรียมตัวไป วิดีโอ แผนที่ตำแหน่ง โมเดล 3 มิติ/AR แหล่งอ้างอิง และลิงก์ไปสถานที่ก่อนหน้า/ถัดไป หน้าเหล่านี้เป็น HTML จริงที่สร้างจาก `assets/js/data.js` + `content/places/<id>.json` ด้วย `npm run build:places` (รวมอยู่ใน `npm run build`; สร้าง `sitemap.xml` และ `robots.txt` ให้ด้วย) ลิงก์เก่าแบบ `#sam-yot` จะพาไปหน้าใหม่อัตโนมัติ

**เพิ่มรูปภาพและข้อมูลของแต่ละสถานที่:** ดู [`content/places/README.md`](content/places/README.md) (วางรูปใน `assets/places/<id>/` แล้วเติม `content/places/<id>.json`) โค้ดส่วนที่ใช้ร่วมกันของทุกหน้า (ธีม, 3 มิติ, AR) อยู่ใน `assets/js/common.js`

**หน้าโหลดตอนเปลี่ยนหน้า:** เมื่อกดลิงก์ภายในเว็บไปหน้าสถานที่หรือกลับหน้าแรก จะมีฉากโหลด (ตราจังหวัดเต้นเบา ๆ) ขึ้นทันที และคงอยู่จนหน้าใหม่โหลดเสร็จจึงจางหาย (ไม่มีจอขาวคั่น) ตัวควบคุมอยู่ใน `assets/js/loader.js` ส่วนหน้าตาเป็น CSS (`html.pl-boot` ใน `src/input.css`) ชี้ลิงก์ค้างไว้ก็ prefetch หน้าล่วงหน้าให้เร็วขึ้น

## หน้า 404

`404.html` สร้างจาก `content/404.json` ด้วย `npm run build` GitHub Pages จะแสดงหน้านี้อัตโนมัติเมื่อเปิดที่อยู่ที่ไม่มี (มีตราจังหวัด ปุ่มกลับหน้าแรก รายการสถานที่ทั้ง 10 แห่ง และเดาหน้าที่หาจากส่วนท้ายของที่อยู่ เช่น `/places/sam-yot` ที่พิมพ์ผิดนิดหน่อย) `npm start` (server.js) ก็แสดงหน้านี้พร้อมสถานะ 404 เช่นกัน

## นโยบายความเป็นส่วนตัว

หน้า `privacy.html` สร้างจาก `content/privacy.json` (ข้อความไทยที่ `th` และคำแปล en/zh/ja ในไฟล์เดียวกัน) ด้วย `npm run build` ใส่อีเมลหรือช่องทางติดต่อที่ `contact.email` / `contact.other` เพื่อแสดงในหน้า ถ้าเปลี่ยนวิธีเก็บข้อมูล (เช่น เพิ่มเครื่องมือวิเคราะห์ ฝังวิดีโอ หรือเปลี่ยนผู้ให้บริการสมุดเยี่ยม) ต้องแก้นโยบายให้ตรงและเปลี่ยนวันที่ปรับปรุงล่าสุด เนื้อหาเป็นแบบร่างที่เขียนให้ตรงกับการทำงานของเว็บ ไม่ใช่คำปรึกษาทางกฎหมาย ควรให้ผู้รู้ด้านกฎหมายตรวจก่อนใช้งานจริงจัง

## สมุดเยี่ยมและรีวิวสถานที่แบบ PHP + MySQL (โฮสติ้งทั่วไป)

ทางเลือกแทน Cloudflare Worker สำหรับโฮสต์ที่มี PHP + MySQL (โค้ดอยู่ใน `deploy/php/`):

- `api/guestbook.php` สมุดเยี่ยม (สัญญาเดียวกับ `server.js`/Worker หน้าเว็บเดิมใช้ได้ไม่ต้องแก้) — ข้อความ **แสดงทันที**
- `api/reviews.php` รีวิวสถานที่ — ต้องให้คะแนนดาว 1–5 และ **รอผู้ดูแลอนุมัติ** จึงแสดงในส่วน "รีวิวจากผู้เข้าชม" ท้ายหน้าสถานที่ (`assets/js/reviews.js`; ซ่อนไว้ถ้าไม่ได้ตั้ง `reviewsApi` ใน `assets/js/config.js`)
- `admin/` หน้าผู้ดูแลล็อกอินด้วยรหัสผ่าน (อนุมัติ/ซ่อน/ลบ) · `schema.sql` ตารางเดียว `lop_reviews` (utf8mb4) · `api/config.sample.php` ตั้งค่าฐานข้อมูล/รหัสผ่าน/การจำกัดความถี่
- อีเมลแจ้งเตือนผู้ดูแลเมื่อมีรีวิวใหม่ (`notify_email` ใน config ส่งด้วย `mail()` กันท่วมด้วย `notify_min_interval` มีปุ่มส่งอีเมลทดสอบในหน้าผู้ดูแล)
- CAPTCHA กันสแปม: `api/captcha.php` — ค่าเริ่มต้นเป็น proof-of-work ในเบราว์เซอร์ (ไม่มีบริการภายนอก) หรือเลือก Cloudflare Turnstile ใน config (`captcha`)
- ความปลอดภัย: prepared statement ทุกคำสั่ง SQL, ตัดอักขระควบคุม, ห้ามลิงก์, ช่องล่อบอต, จำกัดความถี่ต่อผู้ใช้/ต่อสถานที่/ทั้งระบบ (เก็บเฉพาะค่าแฮชของ IP), ตรวจ Origin, ข้อความแสดงด้วย `textContent`, หน้าผู้ดูแลมี CSRF token + เซสชันแบบ HttpOnly/SameSite, ไฟล์ภายในถูกบล็อกด้วย `.htaccess`

สร้างชุดติดตั้ง: `npm run package:php -- --site https://ชื่อโดเมน/` (แบบสแตติกไม่มีฐานข้อมูล: `npm run package:static -- --site https://ชื่อโดเมน/`) ได้ `…-site-php.zip` (เว็บ + `api/` + `admin/`), `schema.sql` และ `INSTALL.php.th.md` (ขั้นตอน cPanel + phpMyAdmin) ชุดนี้มี **ตัวช่วยติดตั้งผ่านเว็บ** `install.php` (ตรวจความพร้อม → ทดสอบฐานข้อมูล → ตั้งรหัสผู้ดูแล → สร้างตารางและไฟล์ตั้งค่า → ลบตัวเองได้) ทำงานแบบเดียวกับตัวช่วยของโปรเจกต์ Payroll-System · หมายเหตุ: ทดสอบกับ PHP 8.3 + MariaDB 10.11 (นำเข้า schema, ส่ง/อนุมัติ/ซ่อน/ลบ, จำกัดความถี่, XSS, SQL injection, ตรวจ Origin); การบล็อกไฟล์ด้วย `.htaccess` ขึ้นกับ Apache/LiteSpeed ของโฮสต์ ต้องตรวจตามคู่มือหลังติดตั้ง

## ที่อยู่หลักของเว็บ (canonical)

เว็บหลักคือ `https://centralthaiheritage.com/` ตั้งไว้ใน `site.config.json` (`canonicalUrl`) และใช้เป็น `canonical`, `hreflang`, `og:url`, JSON-LD และ `sitemap.xml` ของทุกหน้า ส่วนสำเนาบน GitHub Pages เป็นฉบับสำรอง: หน้าทุกหน้าชี้ canonical ไปที่เว็บหลัก เพื่อไม่ให้เสิร์ชเอนจินนับเป็นเนื้อหาซ้ำ และไม่ประกาศ sitemap ของตัวเอง (`robots.txt` บน GitHub Pages ไม่มีบรรทัด Sitemap) ภาพแชร์ลิงก์ (`og:image`) ชี้ที่ `previewUrl` (GitHub Pages) เพื่อให้เปิดได้เสมอแม้เว็บหลักยังไม่ขึ้น เปลี่ยนโดเมนหลักโดยแก้ `canonicalUrl` แล้ว `npm run build` (และแก้บรรทัด `canonical`/`og:url` ใน `index.html` ให้ตรงกัน)

## ติดตั้งลงโฮสต์จริง (นอก GitHub Pages)

```bash
npm run build
npm run package -- --site https://ชื่อโดเมน/        # ใส่ที่อยู่จริง (รองรับโฟลเดอร์ย่อย เช่น https://example.com/lopburi/)
```

ได้โฟลเดอร์ `dist/` ที่มี `site/` (เนื้อหาเว็บ + `.htaccess`), `nginx.conf.example`, `INSTALL.th.md` (คู่มือติดตั้งภาษาไทย: cPanel/FTP, VPS nginx, Netlify/Cloudflare Pages) และไฟล์ `<โดเมน>-site.zip` สคริปต์ (`tools/package-site.mjs`) แทนที่ที่อยู่ GitHub Pages ด้วยที่อยู่จริงในทุกหน้า (canonical, hreflang, ภาพแชร์ลิงก์, sitemap, robots), ตัดไฟล์สำรองสำหรับเปิดแบบ `file://` (~44 MB) ออก, เปลี่ยนข้อความผู้ให้บริการโฮสติ้งในนโยบายความเป็นส่วนตัวเป็นข้อความทั่วไป และตั้ง `<base>` ของหน้า 404 ตามที่อยู่ (`--guestbook-api URL` ใส่ที่อยู่ API สมุดเยี่ยมให้ด้วย) แม่แบบไฟล์ตั้งค่าอยู่ใน `deploy/`

## หน้าแยกตามภาษา (en / zh / ja)

เว็บมี 4 ฉบับ: ไทยอยู่ที่ราก (`/`, `/places/sam-yot.html`) และภาษาอื่นอยู่ในโฟลเดอร์ `en/`, `zh/`, `ja/` (`/en/`, `/zh/places/sam-yot.html`, `/ja/privacy.html`) เพื่อให้ค้นเจอและแชร์ด้วยภาษานั้นได้ แต่ละหน้ามี `canonical` ของตัวเอง, `hreflang` ครบทุกภาษา + `x-default`, `og:locale` และ JSON-LD ตามภาษา และ `sitemap.xml` ลิสต์ทุกหน้า × ทุกภาษา (48 URL) พร้อมลิงก์ภาษาอื่น

**สร้างอย่างไร:** `npm run build` (`tools/build-places.mjs`) สร้างหน้าไทยแล้วแปลข้อความ/แอตทริบิวต์ทั้งหน้าด้วยพจนานุกรมชุดเดียวกับเบราว์เซอร์ (`i18n/*.json` + คำแปลใน `content/privacy.json`, `content/404.json`; โค้ดแปลอยู่ใน `tools/lib/i18n-node.mjs` ใช้กติกาเดียวกับ `assets/js/i18n.js`) จึงไม่ต้องเขียนหน้าแยกเอง เพิ่ม/แก้คำแปลที่ `i18n/<code>.json` แล้ว build ใหม่ ไฟล์ในโฟลเดอร์ `en/ zh/ ja/` เป็นผลลัพธ์ที่สร้างอัตโนมัติ อย่าแก้ตรง ๆ ส่วนเนื้อหาที่เพิ่มใน `content/places/*.json` เป็นภาษาไทย จะแสดงเป็นไทยในทุกภาษาจนกว่าจะเพิ่มคำแปล

**การเปลี่ยนภาษา:** เมนูภาษาเป็นลิงก์ไป URL ของหน้าเดียวกันในภาษาที่เลือก และจำภาษาที่เลือกไว้ (`localStorage`) ครั้งต่อไปที่เปิดหน้าไทย ระบบพาไปหน้าภาษานั้นอัตโนมัติ (`assets/js/loader.js`) ผู้ใช้ใหม่และบอตไม่มีค่าที่จำไว้จึงไม่ถูกพาไปไหน ตั้งใจไม่เดาภาษาจากเบราว์เซอร์แล้วเปลี่ยนหน้าให้ เพราะเสิร์ชเอนจินควรเห็นหน้าไทยที่ URL ไทย ใส่ `?lang=en` ต่อท้ายหน้าไทยเพื่อดูคำแปลแบบแปลในเบราว์เซอร์ (ใช้ทดสอบ) หน้า 404 มีฉบับเดียวและแปลในเบราว์เซอร์

**ส่วนที่สคริปต์สร้างทีหลัง** (การ์ดสถานที่ ไทม์ไลน์ เส้นทาง สภาพอากาศ ฯลฯ ที่ `app.js` วาดจาก `data.js`) ไม่ได้อยู่ใน HTML ที่สร้างไว้ แต่แปลตอนโหลดหน้าตามภาษาของ URL (Googlebot รัน JavaScript จึงเห็น) ส่วนหน้าสถานที่และหน้านโยบายความเป็นส่วนตัวเป็น HTML แปลครบตั้งแต่ต้น

## ภาพปกโมเดล 3 มิติ (กดก่อนค่อยโหลด)

เพื่อให้หน้าเว็บเบา ทุกจุดที่มี 3 มิติ (ไดโอรามาหน้าแรก, หน้าสถานที่ทั้ง 10 แห่ง, แผนที่จังหวัด) จะแสดง **ภาพปก** ก่อน และโหลดไฟล์ `.glb` กับสร้าง WebGL เมื่อผู้ใช้กดเท่านั้น (ตอนเปิดหน้าไม่มีการดาวน์โหลด `.glb` เลย) ภาพปกอยู่ใน `assets/poster/<id>-day|night.webp` (กลางวัน/กลางคืน รวม ~0.5 MB) และสร้างอัตโนมัติจากโมเดลจริง:

```bash
npm i -D playwright && npx playwright install chromium   # ครั้งแรกครั้งเดียว
npm run posters                                          # สร้างทั้งหมด (เพิ่ม -- --software ถ้าเครื่องไม่มี GPU)
npm run posters -- sam-yot map                           # เฉพาะบางภาพ (hero, map หรือ id สถานที่)
```

ทุกครั้งที่เปลี่ยน/เพิ่มโมเดล ให้รัน `npm run posters` แล้ว commit ภาพใหม่ ถ้าไม่มีภาพปก ปุ่มยังใช้งานได้ (แสดงพื้นหลังเปล่าพร้อมปุ่ม "แตะเพื่อดู 3 มิติ")

**เพิ่มโมเดลของสถานที่อื่น:** ย่อไฟล์ด้วย `npm run shrink` วางใน `assets/model/` แล้วใส่ `glb: { url, ar, credit }` ที่สถานที่นั้นใน `assets/js/data.js` (ดูตัวอย่างของ `sam-yot`) จากนั้นรัน `npm run posters`

## โมเดล 3 มิติที่ใช้ในเว็บ

โมเดลที่ปั้นเอง: ครบทั้ง 10 สถานที่ (พระปรางค์สามยอด, ศาลพระกาฬ, ปรางค์แขก, วัดเขาวงพระจันทร์, วัดเสาธงทอง, บ้านวิชาเยนทร์, วัดไลย์, วัดพระศรีรัตนมหาธาตุ, วัดนครโกษา, พระนารายณ์ราชนิเวศน์) และแผนที่ทั้งจังหวัด ไฟล์ต้นฉบับและภาพอ้างอิงเก็บใน `source-models/` (ไม่ถูกเผยแพร่) ไฟล์ที่เว็บใช้อยู่ใน `assets/model/` (`<id>.glb` สำหรับเว็บ, `<id>.ar.glb` สำหรับ AR)

## ย่อไฟล์โมเดล .glb ก่อนอัปโหลด

GitHub ไม่รับไฟล์เกิน 100 MB ให้ย่อบนเครื่องก่อน commit (ต้นฉบับ 46 MB ย่อเหลือ ~2 MB ใน ~10 วินาที):

```bash
npm install                                   # ครั้งแรกครั้งเดียว
npm run shrink -- ต้นฉบับ.glb --out assets/model/prang-sam-yot.glb --ar 0.4
```

ได้ไฟล์เว็บ (meshopt + WebP) และไฟล์ `.ar.glb` สำหรับ AR (ไม่บีบอัด จัดกึ่งกลาง วางบนพื้น กว้าง 0.4 ม.) ตัวเลือก `--ratio` `--texture` `--target` ดูที่หัวไฟล์ `tools/shrink-glb.mjs` ถ้าไฟล์ยังใหญ่กว่าเป้า (ค่าเริ่มต้น 8 MB) สคริปต์จะลดคุณภาพให้เองทีละขั้น ไฟล์ต้นฉบับไม่ต้องอัปโหลดขึ้น git

## แผนที่ 3 มิติทั้งจังหวัด

ส่วน "แผนที่ 3 มิติทั้งจังหวัด" (`#map3d`) ใช้โมเดลที่เจ้าของโปรเจกต์ปั้น: ลากเพื่อหมุน/เอียง, Ctrl + ล้อเมาส์ หรือหนีบสองนิ้วเพื่อซูม, ปุ่ม +/−/รีเซ็ต, ปุ่มลูกศรบนคีย์บอร์ด (+/− ซูม, Esc รีเซ็ต) แตะหมุด แตะที่ตัวแผนที่ใกล้สถานที่ หรือเลือกจากแถบรายชื่อ กล้องจะบินเข้าไปและขึ้นการ์ดข้อมูลพร้อมลิงก์ไปอ่านรายละเอียดและดูโมเดลอาคารแบบ AR มีปุ่ม AR ของแผนที่ทั้งแผ่น (กว้าง ~50 ซม.)

- ไฟล์: `assets/model/lopburi-province.glb` (2.5 MB สำหรับเว็บ: ลดจาก 1.29M เหลือ ~155k สามเหลี่ยม + meshopt + WebP) และ `lopburi-province.ar.glb` (6.2 MB สำหรับ AR ไม่บีบอัด) ต้นฉบับ 48 MB อยู่ที่ `source-models/lopburi-province.original.glb`
  ```bash
  npx @gltf-transform/cli optimize source-models/lopburi-province.original.glb assets/model/lopburi-province.glb \
    --compress meshopt --simplify true --simplify-ratio 0.12 --simplify-error 0.0008 --texture-compress webp --texture-size 2048 --no-instance --no-palette
  # ไฟล์ AR: optimize แบบ --compress false --texture-compress false, resize 1024, แล้ว node tools/make-ar-glb.mjs in.glb out.glb 0.5
  ```
- ตำแหน่งหมุดเก็บที่ `PROVINCE_MODEL.hotspots` ใน `assets/js/data.js` (พิกัด x,z ในหน่วยของไฟล์ต้นฉบับ เหนืออยู่บนเมื่อมองจากด้านบน) ความสูงคำนวณจากผิวโมเดลเอง ถ้าเปลี่ยนโมเดลต้องวัดพิกัดใหม่ ปัจจุบันโมเดลมี 7 สถานที่ (ไม่มีปรางค์แขก วัดเสาธงทอง วัดนครโกษา)
- ตัวดู: `createMapViewer` ใน `src/three-scenes.js` ใช้ renderer ของตัวเอง โหลดโมเดลเมื่อเลื่อนใกล้ถึง ถ้าไม่มี WebGL จะแจ้งและให้ใช้แผนที่ภาพแทน

## AR (ดูโมเดลบนโต๊ะจริง)

ทุกการแสดงผล 3 มิติมีปุ่ม **ดูแบบ AR** (ไดโอรามาหน้าแรก + 10 สถานที่) เปิดหน้าต่างดู 3 มิติเต็มจอด้วย [`<model-viewer>`](https://modelviewer.dev/) ของ Google ถ้าอุปกรณ์รองรับจะมีปุ่ม "ดูใน AR" (WebXR บน Android Chrome, Scene Viewer บน Android, Quick Look บน iPhone/iPad)

- `src/ar.js` → `assets/js/ar.js` (~1 MB) โหลดเฉพาะตอนกดปุ่ม ใช้ three 0.183 (`three-mv`) แยกจากตัวเรนเดอร์หลัก (three 0.187) เพราะ model-viewer 4.4 ผูกกับ 0.183 (alias ตอน build)
- โมเดลที่สร้างด้วยโค้ด: `LopburiGL.exportGLB(type)` ส่งออก .glb ตอนกด (กว้างราว 40 ซม. พร้อมฐานดินเผา ก้นแตะพื้น) ไม่ต้องมีไฟล์สำรอง ผ่านตัวตรวจ Khronos glTF Validator ครบ 10 แบบ
- โมเดลที่ปั้นเอง: ใช้ไฟล์ AR แยก `assets/model/prang-sam-yot.ar.glb` (2.5 MB, ไม่บีบอัดแบบ meshopt/WebP เพราะ Scene Viewer/Quick Look ไม่รองรับ) สร้างด้วย `tools/make-ar-glb.mjs` (ขั้นตอนอยู่ในคอมเมนต์ต้นไฟล์) กำหนดที่ฟิลด์ `glb.ar` ใน `assets/js/data.js`
- ข้อกำหนด: ต้องเปิดผ่าน **HTTPS** (หรือ localhost) และอุปกรณ์ที่รองรับ AR ถ้าไม่รองรับจะยังดู 3 มิติได้ พร้อมข้อความอธิบาย
- ยังไม่ได้ทดสอบ AR บนอุปกรณ์จริง (ทดสอบได้เฉพาะการแสดงผล 3 มิติ การส่งออก และการจัดการกรณีไม่รองรับ)

## โมเดล 3 มิติของเจ้าของโปรเจกต์ (.glb)

- `assets/model/prang-sam-yot.glb` (2.7 MB) คือโมเดลพระปรางค์สามยอดที่ปั้นเอง ใช้ในไดโอรามาหน้าแรกและหน้ารายละเอียด โหลดแบบ progressive: แสดงโมเดลจำลองก่อน แล้วสลับเป็นไฟล์จริงเมื่อโหลดเสร็จ ถ้าโหลดไม่ได้จะใช้โมเดลจำลองต่อ
- ไฟล์ต้นฉบับ 71 MB (2.1 ล้านสามเหลี่ยม) เก็บไว้ที่ `source-models/prang-sam-yot.original.glb` (อยู่นอกโฟลเดอร์ที่เว็บเสิร์ฟ)

- ใส่ .glb ให้สถานที่อื่น: เพิ่มฟิลด์ `glb: { url, credit }` ใน `assets/js/data.js`

## หลายภาษา (ไทย / English / 简体中文 / 日本語)

ปุ่มภาษา (ไอคอนโลก) มุมขวาบน สลับทั้งหน้าโดยไม่โหลดหน้าใหม่ และจำค่าที่เลือกไว้ (`localStorage` + `?lang=xx` ใน URL) ถ้ายังไม่เลือกจะดูภาษาของเบราว์เซอร์ (ไม่รองรับ → ไทย) รองรับคีย์บอร์ด (ลูกศร/Esc) และเปลี่ยน `<html lang>`, ชื่อหน้า, meta และฟอนต์ตามภาษา (Noto Sans SC/JP โหลดเฉพาะเมื่อเลือก)

- **ภาษาไทยคือต้นฉบับ** ในหน้าเว็บและ `assets/js/data.js` ภาษาอื่นเป็นพจนานุกรม "ข้อความไทย → คำแปล" ที่ `i18n/<code>.json` (แก้ไขตรงนี้) แล้ว `npm run build` สร้าง `assets/js/lang/<code>.js` (~90 KB ต่อภาษา โหลดเฉพาะภาษาที่เลือก)
- ตัวแปล `assets/js/i18n.js` สแกนข้อความและ `aria-label`/`alt`/`title`/`placeholder` และเฝ้าดูเนื้อหาที่ `app.js` สร้างภายหลัง (MutationObserver) จึงไม่ต้องแก้เทมเพลต เก็บข้อความไทยต้นฉบับไว้ สลับกลับไทยได้เหมือนเดิมทุกตัวอักษร ถ้าไม่มีคำแปลจะแสดงข้อความไทยแทน (ไม่ว่าง)
- ข้อความที่มีตัวแปรใช้ `{0}` `{1}` เช่น `"{0} ข้อความจากผู้มาเยือน"`; ในโค้ดเรียก `T('ข้อความ', ...ค่า)`; วันที่ใช้ locale ของภาษาที่เลือก
- เพิ่มภาษาใหม่: สร้าง `i18n/<code>.json` แล้วเพิ่มรายการใน `LANGS` ของ `assets/js/i18n.js`
- ที่ไม่แปลโดยตั้งใจ: ชื่อบทความ/สื่อของแหล่งอ้างอิงภายนอก (ใช้ชื่อเดิม), คำค้น YouTube ภาษาไทย, ป้ายกำกับอังกฤษแบบแบรนด์ (Heritage Pass) ในโหมดอังกฤษชื่อสถานที่ภาษาอังกฤษใต้ชื่อจะสลับเป็นชื่อไทย
- คำแปลภาษาอังกฤษ/จีน/ญี่ปุ่นเขียนโดย AI ควรให้เจ้าของภาษาตรวจ โดยเฉพาะชื่อเฉพาะ (ชื่อสถานที่ภาษาจีน/ญี่ปุ่นเป็นการถอดเสียง/แปลที่ผมเลือกเอง ไม่ใช่ชื่อทางการ)

## อนิเมชัน (anime.js)

ชั้นอนิเมชันใช้ [anime.js](https://animejs.com/) v4 (MIT) รวมเป็น `src/motion.js` → `assets/js/motion.js` (~39 KB) เปิดเป็น `window.Motion`: เผยการ์ดทยอยเมื่อเลื่อนถึง (เลื่อนขึ้น + เฟด + stagger), นับเลขขึ้นที่สถิติ, ตราบนแบนเนอร์ลอยเบา ๆ, แฉกพระอาทิตย์ในวิดเจ็ตอากาศหมุน (ตอนกลางวันฟ้าโปร่ง), แท่งบาร์โค้ดตั้งขึ้นทีละแท่ง, หมุดบนแผนที่ 3 มิติเด้งแบบสปริง, การ์ดข้อมูล/หน้าต่าง AR เลื่อนเข้า, ปุ่มโหมดกลางวัน/กลางคืนเด้งพร้อมแสงวาบ, ข้อความสมุดเยี่ยมใหม่เลื่อนเข้า ทุกอย่างเคารพ `prefers-reduced-motion` (ข้ามอนิเมชัน) และถ้าไฟล์ไม่โหลดก็ถอยไปใช้การเผยธรรมดา

## เคอร์เซอร์และลูกเล่นเมาส์

ชุดลูกเล่นเมาส์ใน `src/motion.js` (`Motion.cursor()` และ `Motion.ripples()`) ใช้ anime.js ทำ: จุด + วงแหวนเคอร์เซอร์ที่ตามอย่างนุ่มนวล (`createAnimatable`) วงแหวนขยายเมื่อชี้ปุ่ม/ลิงก์ และขึ้นคำว่า "ลาก" เมื่อชี้โมเดล 3 มิติ/แผนที่ 3 มิติ, ประกายทองตามรอยเมาส์และระเบิดประกายเมื่อคลิกปุ่ม, ปุ่มถูกดึงเข้าหาเคอร์เซอร์เล็กน้อย (magnetic), แสงสปอตไลต์ตามเมาส์บนการ์ด และการ์ดตั๋ว Heritage Pass เอียงตามเมาส์ (`data-tilt`), ระลอกคลื่นตอนแตะ/คลิก

- เปิดเฉพาะอุปกรณ์ที่มีเมาส์ (`hover: hover` + `pointer: fine`) มือถือ/แท็บเล็ตได้เฉพาะระลอกตอนแตะ
- ปิดทั้งหมดเมื่อผู้ใช้ตั้งค่า `prefers-reduced-motion` (ใช้เคอร์เซอร์ระบบ)
- เคอร์เซอร์ระบบกลับมาอัตโนมัติเหนือช่องกรอกข้อความ/เลือก และเมื่อเปิดหน้าต่าง (dialog) AR
- สีประกายและเคอร์เซอร์เปลี่ยนตามโหมดกลางวัน/กลางคืน (ตัวแปร `--cursor`, `--spark-*` ใน `src/input.css`)
- หมายเหตุ: คลาสที่สร้างจาก JS (`cur-*`, `sparkle`, `tap-ripple`) ต้องให้ Tailwind สแกนไฟล์นั้น จึงเพิ่ม `src/motion.js` และ `assets/js/i18n.js` ใน `content` ของ `tailwind.config.js`

## โหมดกลางวัน / กลางคืน

ปุ่มพระอาทิตย์/พระจันทร์มุมขวาบน สลับธีมทั้งหน้า จำค่าที่เลือกไว้ (`localStorage`) และตามการตั้งค่าระบบ (`prefers-color-scheme`) ถ้ายังไม่เคยเลือก ธีมทำด้วยตัวแปร CSS (`--cream-*`, `--ink-*`, `--paper`, เงา) ใน `src/input.css` ที่ Tailwind อ้างถึงผ่าน `tailwind.config.js` จึงสลับสีทุกคลาสโดยไม่ต้องเขียน `dark:` ซ้ำ ตัวอักษรสว่างบนพื้นเข้มใช้สี `snow-*` ที่ไม่เปลี่ยนตามโหมด ฉาก 3 มิติเปลี่ยนเป็นแสงจันทร์สีน้ำเงินพร้อมไฟตะเกียงอุ่นด้านหลัง (`LopburiGL.setNight`)

## สมุดเยี่ยม

  (หากต้องการแชร์บนโฮสต์ static ให้ชี้ `API` ใน `assets/js/app.js` ไปยัง backend ของคุณที่ตอบ `GET/POST` รูปแบบเดียวกับ `server.js`)

## ภาพถ่ายและวิดีโอ — เครดิต (สำคัญ)

เซสชันที่สร้างงานนี้ออกอินเทอร์เน็ตไปยัง Wikipedia / Wikimedia Commons / YouTube ไม่ได้ จึง **ไม่ได้ฝังภาพถ่ายจริงหรือวิดีโอของใคร** และไม่ได้แต่ง ID วิดีโอขึ้นมาเอง

- ภาพถ่ายจริง: ใส่ใน `assets/js/data.js` ที่ฟิลด์ `photo` ของแต่ละสถานที่ — เว็บจะแสดงผู้ถ่าย สัญญาอนุญาต และลิงก์ต้นฉบับใต้ภาพให้อัตโนมัติ
  ```js
  photo: { src: 'assets/img/sam-yot.jpg', alt: '...', author: 'ชื่อผู้ถ่าย', license: 'CC BY-SA 4.0',
           licenseUrl: 'https://creativecommons.org/licenses/by-sa/4.0/', sourceUrl: 'https://commons.wikimedia.org/wiki/File:...' }
  ```
- วิดีโอ: ตอนนี้เป็นปุ่มค้นหา YouTube (ลิงก์ใช้ได้จริงเสมอ) ถ้าเลือกคลิปแล้วให้ใส่ `video: { id, title, channel, url }` เว็บจะฝังคลิป (youtube-nocookie) พร้อมชื่อช่องและลิงก์ต้นทาง
- ภาพแผนที่ไอโซเมตริก (ต้นฉบับ `source-models/map-isometric.original.webp`) ย่อเป็น `assets/img/lopburi-map-768.webp` / `lopburi-map-1536.webp` เป็นภาพที่เจ้าของโปรเจกต์จัดเตรียมให้ พิกัดหมายเลขที่กดได้เก็บเป็นเปอร์เซ็นต์ของภาพที่ฟิลด์ `map` ใน `assets/js/data.js` (ถ้าเปลี่ยนภาพแผนที่ต้องปรับค่านี้ด้วย)

## ความถูกต้องของข้อมูล

ข้อมูลรวบรวมจากผลค้นหาเว็บ (33 แหล่งที่ระบุในหน้า "เครดิต") เนื้อหาใดที่ค้นไม่พบจะเขียนบอกตรง ๆ ว่าไม่พบ (เช่น ปีสร้างวัดพระศรีรัตนมหาธาตุ, ประวัติศาลพระกาฬ) ไม่เติมตัวเลขเอง
เวลาเปิด/ค่าเข้าชมไม่ได้ยืนยัน (ยกเว้นบ้านวิชาเยนทร์ซึ่งมีแหล่งระบุและติดดอกจันไว้) ควรตรวจกับกรมศิลปากรก่อนเผยแพร่

|---|---|
| `index.html` | โครงหน้า (Tailwind utility classes) |
