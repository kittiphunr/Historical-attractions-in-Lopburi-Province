# เปิดสมุดเยี่ยมและรีวิวสถานที่ (PHP + MySQL) บน {{HOST}}

ชุดนี้เพิ่มระบบฐานข้อมูลให้เว็บ {{SITE}}

- **สมุดเยี่ยม** (หน้าแรก): ข้อความที่ผู้เข้าชมเขียน **แสดงทันที** ทุกคนเห็นร่วมกัน ผู้ดูแลซ่อน/ลบภายหลังได้
- **รีวิวสถานที่** (หน้าสถานที่แต่ละแห่ง): ต้องให้คะแนนดาว 1–5 และ **รอผู้ดูแลอนุมัติก่อนจึงแสดง** พร้อมคะแนนเฉลี่ยและจำนวนรีวิว
- **หน้าผู้ดูแล** `{{SITE}}admin/`: ดูรายการรอตรวจ อนุมัติ ซ่อน ลบ

ต้องการโฮสต์ที่มี **PHP 7.4 ขึ้นไป (แนะนำ 8.x)** พร้อม **PDO MySQL** และ **ฐานข้อมูล MySQL / MariaDB** (cPanel ส่วนใหญ่มีครบ) ถ้ายังไม่ได้ติดตั้งเว็บหลัก ให้ทำตาม `INSTALL.th.md` ก่อน

## วิธีเร็ว: ตัวช่วยติดตั้งผ่านเว็บ (แนะนำ ประมาณ 5 นาที)

1. สร้างฐานข้อมูล + ผู้ใช้ใน cPanel (ข้อ 1 ด้านล่าง) จดชื่อฐานข้อมูล ผู้ใช้ และรหัสผ่านไว้
2. อัปโหลดเนื้อหาโฟลเดอร์ `site/` ทั้งหมดไปที่ `public_html` (มี `install.php`, `api/`, `admin/` รวมอยู่แล้ว ไม่ต้องนำเข้า `schema.sql` เอง)
3. เปิด **{{SITE}}install.php** ทำตาม 4 ขั้น: ตรวจความพร้อม → กรอกข้อมูลฐานข้อมูล (ทดสอบการเชื่อมต่อให้) → ตั้งรหัสผ่านผู้ดูแล → ติดตั้ง
   ตัวช่วยจะสร้างตาราง สร้าง `lopburi-config.php` ให้ (เก็บไว้นอกโฟลเดอร์เว็บถ้าเขียนได้ ไม่เช่นนั้นเป็น `api/config.php`) และสุ่ม `ip_salt` ให้เอง
4. ติดตั้งเสร็จ กดปุ่ม **ลบ install.php** เพื่อลบตัวช่วยออกจากเซิร์ฟเวอร์ แล้วทดสอบตามหัวข้อ "ตรวจสอบ" ด้านล่าง (ถ้าอยากป้องกันเพิ่มก่อนติดตั้ง ตั้งตัวแปรสภาพแวดล้อม `LOPBURI_INSTALL_KEY` ได้)

> ตัวช่วยล็อกตัวเองเมื่อพบไฟล์ตั้งค่า (ติดตั้งซ้ำไม่ได้ ต้องลบไฟล์ตั้งค่าก่อน) ถ้าตัวช่วยใช้ไม่ได้ ให้ทำด้วยมือตามขั้นตอนด้านล่าง

## ขั้นตอนทำด้วยมือ (ถ้าไม่ใช้ตัวช่วย) (ประมาณ 15 นาที)

### 1) สร้างฐานข้อมูล (cPanel → MySQL® Databases)
1. สร้างฐานข้อมูลใหม่ เช่น `lopburi` (cPanel จะใส่ชื่อบัญชีนำหน้าให้ เช่น `abc123_lopburi`)
2. สร้างผู้ใช้ฐานข้อมูล พร้อมรหัสผ่านที่เดายาก (กดปุ่ม Password Generator ได้) จดชื่อผู้ใช้และรหัสผ่านไว้
3. หัวข้อ **Add User To Database** เลือกผู้ใช้และฐานข้อมูลที่สร้าง ให้สิทธิ์ **ALL PRIVILEGES**

### 2) สร้างตาราง (phpMyAdmin)
เปิด **phpMyAdmin** → คลิกฐานข้อมูลที่สร้าง → แท็บ **นำเข้า (Import)** → เลือกไฟล์ `schema.sql` ในชุดนี้ → กด **ดำเนินการ (Go)** จะได้ตาราง `lop_reviews` (สมุดเยี่ยม/รีวิว) กับ `lop_place_content`, `lop_place_revisions` (ระบบจัดการเนื้อหาสถานที่ — ถ้าข้ามขั้นนี้ ระบบจะสร้างให้เองตอนเปิดหน้า `admin/places.php` เมื่อผู้ใช้ฐานข้อมูลมีสิทธิ์ CREATE)

### 3) อัปโหลดไฟล์ API และหน้าผู้ดูแล
ในชุดนี้ โฟลเดอร์ `site/` มี `api/`, `admin/`, `uploads/` และไฟล์ `place.php` เพิ่มจากชุดเว็บเดิม (และ `.htaccess` ที่มีกฎส่งหน้าสถานที่ผ่าน `place.php`) อัปโหลดทั้งหมดนี้ — **อัปเดตเว็บครั้งต่อไป อย่าลบโฟลเดอร์ `uploads/`** เพราะเก็บรูปที่อัปโหลดไว้ — อัปโหลดโฟลเดอร์ `api/` และ `admin/` (และ `assets/js/config.js` ที่แก้แล้ว) ไปไว้ในโฟลเดอร์เว็บของโดเมน (`public_html`) ให้ได้ `public_html/api/reviews.php` และ `public_html/admin/index.php` ไฟล์ `.htaccess` ในโฟลเดอร์ทั้งสอง (ไฟล์ซ่อน) ต้องขึ้นไปด้วย เพราะบล็อกไม่ให้เปิดไฟล์ภายใน

### 4) ตั้งค่า `config.php`
1. เปิดไฟล์ `site/api/config.sample.php` คัดลอกเนื้อหาไปสร้างไฟล์ใหม่ชื่อ **`lopburi-config.php`** ไว้ **นอก `public_html`** (โฟลเดอร์แม่ของ `public_html` เช่น `/home/ชื่อบัญชี/lopburi-config.php`) — ตำแหน่งนี้เปิดจากเว็บไม่ได้เลย ปลอดภัยที่สุด
   - ถ้าโฮสต์ไม่ให้เข้าถึงโฟลเดอร์นอก `public_html` ให้ตั้งชื่อเป็น `config.php` ไว้ใน `public_html/api/` (มี `.htaccess` บล็อกให้แล้ว แต่ตรวจดูว่าเปิด `{{SITE}}api/config.php` ได้ **403** ไม่ใช่แสดงเนื้อหา)
2. แก้ค่าในไฟล์: `db_name`, `db_user`, `db_pass` (จากข้อ 1) และ `ip_salt` (ข้อความสุ่มยาว ๆ ของคุณเอง)
3. **ห้ามใส่ไฟล์นี้ใน git หรือส่งต่อให้ใคร** มีรหัสผ่านฐานข้อมูล

### 5) ตั้งรหัสผ่านผู้ดูแล
1. เปิด `{{SITE}}admin/` (ขณะ `admin_password_hash` ใน config ยังว่าง) จะเห็นแบบฟอร์ม "ตั้งรหัสผ่านผู้ดูแล"
2. พิมพ์รหัสผ่านที่ต้องการ (ยาวอย่างน้อย 10 ตัวอักษร) กด "สร้างค่าแฮช" คัดลอกบรรทัดที่ได้ไปวางแทน `'admin_password_hash' => '',` ใน config แล้วบันทึกไฟล์
3. รีเฟรช `{{SITE}}admin/` แล้วเข้าสู่ระบบด้วยรหัสผ่านที่ตั้ง

### 6) ตรวจสอบ
1. เปิดหน้าสถานที่ เช่น `{{SITE}}places/sam-yot.html` เลื่อนลงจะเห็นส่วน **"รีวิวจากผู้เข้าชม"** ("ยังไม่มีรีวิว…") ถ้าไม่เห็น แปลว่า API ยังเรียกไม่ได้ (ดูหัวข้อแก้ปัญหา)
2. เขียนรีวิวทดสอบ → จะขึ้นข้อความว่ารอผู้ดูแลตรวจ → เข้า `{{SITE}}admin/` กด **อนุมัติ** → รีเฟรชหน้าสถานที่ รีวิวต้องขึ้นพร้อมคะแนนเฉลี่ย
3. เขียนข้อความในสมุดเยี่ยม (หน้าแรก) → ต้องขึ้นทันที และสถานะบนหน้าเว็บเปลี่ยนเป็น "บันทึกร่วมกันทุกคน (เซิร์ฟเวอร์)"
4. ลบข้อความทดสอบในหน้าผู้ดูแล

## การใช้งานประจำวัน
- เข้า `{{SITE}}admin/` ดูแท็บ **รอตรวจ** (ถ้าเปิดอีเมลแจ้งเตือนตามหัวข้อด้านล่าง จะได้อีเมลเมื่อมีรีวิวใหม่) กด **อนุมัติ/แสดง** รีวิวที่ดี **ซ่อน** หรือ **ลบ** รีวิวที่ไม่เหมาะสมหรือสแปม
- ข้อความจากสมุดเยี่ยมแสดงทันที ตรวจในแท็บ "แสดงแล้ว" (กรองชนิด "สมุดเยี่ยม") และซ่อน/ลบได้เช่นกัน
- ผู้ใช้ขอลบข้อความ (PDPA): ค้นชื่อและข้อความในหน้าผู้ดูแล แล้วกด **ลบ** (ดูนโยบายความเป็นส่วนตัวของเว็บ)
- **สำรองข้อมูล:** phpMyAdmin → ฐานข้อมูล → ส่งออก (Export) ตาราง `lop_reviews` และตารางเนื้อหาสถานที่ (`lop_place_content`, `lop_place_revisions`) หรือใช้ระบบสำรองของโฮสต์

## จัดการเนื้อหาสถานที่ (ตัวแก้ไขข้อความ CKEditor 5)
เข้า `{{SITE}}admin/places.php` (ล็อกอินเดียวกับหน้าสมุดเยี่ยม หรือกดแท็บ **เนื้อหาสถานที่**) เลือกสถานที่และภาษา แล้วแก้ 4 ส่วนของหน้า: **ประวัติศาสตร์ · สถาปัตยกรรม · ไฮไลต์ · เตรียมตัวไป** ด้วยตัวแก้ไขที่มีหัวข้อ ตัวหนา/เอียง ลิงก์ รายการ ตาราง และรูปภาพ

- **ข้อความตั้งต้น:** ส่วนที่ไม่เคยแก้ใช้ข้อความจากตอนสร้างเว็บ (ตัวแก้ไขเปิดมาให้พร้อมแก้) ส่วนที่แก้แล้วเก็บในฐานข้อมูลและขึ้นหน้าเว็บทันที ถ้าแก้ให้เท่ากับข้อความตั้งต้นหรือกด **ใช้ข้อความตั้งต้น** ระบบจะกลับไปใช้ข้อความของเว็บ (ตามการสร้างเว็บใหม่ได้)
- **หลายภาษา:** แก้แยกตามภาษา (ไทย/English/中文/日本語) ภาษาที่ไม่ได้แก้ใช้คำแปลตั้งต้นของเว็บ — ระบบไม่แปลให้เอง
- **ประวัติและย้อนกลับ:** เก็บ 15 ครั้งล่าสุดต่อส่วน กด **ใช้เวอร์ชันนี้** เพื่อย้อน · ถ้าสองคนเปิดแก้ส่วนเดียวกัน คนที่บันทึกทีหลังจะได้ข้อความเตือนและไม่ทับงานของอีกคน
- **รูปภาพ:** กดปุ่มรูปในตัวแก้ไข (หรือลากรูปวาง) — เซิร์ฟเวอร์แปลงเป็น WebP กว้างไม่เกิน 1600 px และลบข้อมูลในไฟล์ (เช่น ตำแหน่ง GPS) เก็บที่ `uploads/places/<สถานที่>/` · รับ JPEG/PNG/WebP ไม่เกิน 8 MB · **ต้องใส่เครดิตผู้ถ่ายและสัญญาอนุญาตในคำบรรยายใต้รูป** และข้อความทางเลือก (alt) ให้ทุกรูป · รูปที่ลบออกจากข้อความแล้วยังค้างในโฟลเดอร์ `uploads/` (ลบเองผ่านตัวจัดการไฟล์ได้)
- **ความปลอดภัย:** ข้อความที่แก้ถูกกรองฝั่งเซิร์ฟเวอร์ให้เหลือเฉพาะแท็กที่อนุญาต (ตัด script/iframe/สไตล์/ลิงก์อันตราย และรูปที่ไม่ได้มาจากการอัปโหลดของระบบ) ทั้งตอนบันทึกและตอนแสดง
- **ข้อจำกัด:** แก้ได้เฉพาะ 4 ส่วนข้างต้น — ชื่อ คำโปรย สรุป ข้อมูลสั้น ๆ ข้างบน หน้าแรก และการ์ดสถานที่ยังมาจากตอนสร้างเว็บ · ถ้าอัปโหลดเว็บเวอร์ชันใหม่ที่เปลี่ยนข้อความตั้งต้น ส่วนที่แก้ไว้แล้วจะยังเป็นข้อความที่แก้ (ไม่ถูกทับ)
- **ต้องมี:** ส่วนขยาย PHP `dom` (กรองข้อความ) และ `gd` ที่รองรับ WebP (อัปโหลดรูป) — ตัวช่วยติดตั้งตรวจให้ · โฮสต์ Apache/LiteSpeed ใช้ `.htaccess` ในชุดได้เลย
- **สำรองข้อมูล:** ส่งออกตาราง `lop_place_content`, `lop_place_revisions` **และสำรองโฟลเดอร์ `uploads/`** ไปพร้อมกัน
- **nginx:** ไม่ใช้ `.htaccess` — เพิ่มกฎนี้ในบล็อก `server` (และตั้ง PHP-FPM ตามหัวข้อแก้ปัญหา) ก่อนบล็อก `location /` (กฎด้านล่างเขียนตามเอกสาร nginx แต่ยังไม่ได้ทดสอบกับ nginx จริง — ตรวจหน้าสถานที่หลังตั้งค่า):
  ```
  rewrite ^/(?:(en|zh|ja)/)?places/([a-z0-9-]+)\.html$ /place.php?lang=$1&id=$2 last;
  location ^~ /uploads/ { location ~ \.php$ { return 403; } }
  ```
- **สัญญาอนุญาต:** ตัวแก้ไข CKEditor 5 ใช้ภายใต้ GPL-2.0 หรือใหม่กว่า (ไฟล์สัญญาอยู่ที่ `admin/assets/LICENSE-ckeditor5.md` และ `COPYING.GPL`) — ถ้าจะแจกจ่ายชุดนี้ต่อให้ผู้อื่น ต้องปฏิบัติตามเงื่อนไข GPL หรือซื้อสัญญาอนุญาตเชิงพาณิชย์จาก CKSource

## จัดการโมเดล 3 มิติ (สถานที่และแผนที่ทั้งจังหวัด)
เข้า `{{SITE}}admin/models.php` (แท็บ **โมเดล 3 มิติ**) เลือกสถานที่หรือ "แผนที่ 3 มิติทั้งจังหวัด" แล้วอัปโหลดไฟล์ `.glb` ใหม่แทนของเดิมได้ทันที ไม่ต้องสร้างเว็บใหม่

- **ฟอร์มอัปโหลด:** ไฟล์โมเดลสำหรับแสดงบนเว็บ (บังคับ) · ไฟล์สำหรับ AR แบบไม่บีบอัด (ไม่บังคับ) · ภาพปกที่แสดงก่อนกดดูโมเดล (ไม่บังคับ) · เครดิตผู้สร้างที่แสดงใต้โมเดล — **ใช้ได้เฉพาะโมเดลที่ผู้สร้างยินยอมให้ใช้ และควรใส่เครดิตและสัญญาอนุญาตให้ครบ**
- **ระบบตรวจไฟล์:** เซิร์ฟเวอร์อ่านโครงสร้างไฟล์ก่อนรับ (ต้องเป็น GLB 2.0 ที่สมบูรณ์ รวมทุกอย่างในไฟล์เดียว ไม่อ้างไฟล์ภายนอก ไม่ใช้ Draco/KTX2 ที่ตัวแสดงของเว็บอ่านไม่ได้) ไฟล์แสดงผลไม่เกิน 20 MB (แนะนำ ≤ 5 MB) ไฟล์ AR ไม่เกิน 40 MB และต้องไม่บีบอัด ไฟล์ที่ไม่ผ่านจะถูกปฏิเสธพร้อมเหตุผล ไม่มีไฟล์ค้าง · ระบบ **ไม่ย่อหรือแก้ไฟล์ให้** ย่อก่อนอัปโหลดด้วย `npm run shrink -- ต้นฉบับ.glb --out ชื่อ.glb --ar 0.4` (ได้ทั้งไฟล์เว็บและ `.ar.glb`)
- **ขีดจำกัดของโฮสต์:** ถ้าไฟล์ใหญ่กว่า `upload_max_filesize`/`post_max_size` ของ PHP หน้าจะแจ้งตัวเลขที่ใช้ได้ (ขอให้โฮสต์เพิ่ม หรืออัปโหลดทีละไฟล์)
- **โมเดลเดิมของเว็บไม่ถูกลบ:** กด **ใช้โมเดลตั้งต้นของเว็บ** เพื่อกลับไปใช้ได้ทุกเมื่อ และมีประวัติโมเดลที่เคยอัปโหลด 5 ครั้งล่าสุดต่อรายการให้ย้อนกลับ (ไฟล์ที่ไม่อยู่ในประวัติแล้วจะถูกลบอัตโนมัติ)
- **ระบบปรับขนาดและวางกึ่งกลางให้เอง** ไม่ต้องตั้งสเกล · **ภาพปกเดิมจะไม่ถูกใช้กับโมเดลใหม่** (เพราะไม่ตรงกัน) ถ้าไม่อัปโหลดภาพปก จะเห็นปุ่ม "แตะเพื่อดู 3 มิติ" ไม่มีภาพ · ภาพแชร์ลิงก์ (og) ยังเป็นภาพเดิมจนกว่าจะสร้างเว็บใหม่ · ถ้าไฟล์เว็บใช้การบีบอัดและไม่มีไฟล์ AR ปุ่ม AR จะใช้ไม่ได้ (ระบบเตือนตอนอัปโหลด)
- **ตำแหน่งหมุดบนแผนที่ 3 มิติ:** ถ้าเปลี่ยนโมเดลแผนที่จังหวัดเป็นรูปทรงอื่น ปรับพิกัด x, z ของหมุดแต่ละจุดได้ในหน้าเดียวกัน (ว่างทั้งคู่ = ใช้ค่าตั้งต้น)
- **หลักการทำงาน:** ไฟล์เก็บที่ `uploads/models/` ข้อมูลอยู่ในตาราง `lop_models`, `lop_model_history`, `lop_settings` และ `.htaccess` ส่ง `assets/js/data.js` ผ่าน `data.php` ซึ่งต่อท้ายด้วยโมเดลที่ตั้งไว้ (ถ้าไม่มีการตั้งค่าหรือฐานข้อมูลใช้ไม่ได้ จะส่ง `data.js` เดิมทุกไบต์ เว็บไม่ล่ม) · nginx: เพิ่ม `rewrite ^/assets/js/data\.js$ /data.php last;` ในบล็อก `server` (ยังไม่ได้ทดสอบกับ nginx จริง) และอนุญาตไฟล์ `.glb` ใน `uploads/`
- **สำรองข้อมูล:** ส่งออกตาราง `lop_models`, `lop_model_history`, `lop_settings` และสำรองโฟลเดอร์ `uploads/` (ทั้ง `places/` และ `models/`)

## การป้องกันสแปมที่มีให้
**CAPTCHA** (ดูหัวข้อถัดไป) · ห้ามใส่ลิงก์ในข้อความ · ตรวจความยาว · ช่องล่อบอต · จำกัดความถี่ต่อผู้ใช้ (สมุดเยี่ยม 3 ข้อความ/10 นาที, รีวิว 3 รายการ/ชั่วโมง และสถานที่เดิมซ้ำได้วันละครั้ง) และต่อทั้งระบบ (ปรับได้ใน `config.php` หัวข้อ `limits`) · เก็บเฉพาะค่าแฮชของ IP (ไม่เก็บ IP จริง) · รีวิวต้องอนุมัติก่อนแสดง 
## อีเมลแจ้งเตือนเมื่อมีรีวิวใหม่
ใส่อีเมลของคุณที่ขั้นที่ 3 ของตัวช่วยติดตั้ง (ช่อง "อีเมลแจ้งเตือน") หรือตั้ง `'notify_email' => 'you@example.com'` ใน config ภายหลัง แล้วเข้า `{{SITE}}admin/` กด **ส่งอีเมลทดสอบ** เพื่อตรวจว่าได้รับจริง
- ส่งด้วยฟังก์ชัน `mail()` ของโฮสต์ ไม่ต้องตั้ง SMTP ผู้ส่งคือ `no-reply@{{HOST}}` (เปลี่ยนได้ที่ `'notify_from'` ควรเป็นอีเมลของโดเมนเดียวกับเว็บ) ถ้าอีเมลเข้าสแปมให้ตั้ง SPF/DKIM ของโดเมนตามที่โฮสต์แนะนำ
- เนื้อหา: สถานที่ คะแนน ชื่อที่แสดง ข้อความรีวิว จำนวนที่รอตรวจ และลิงก์เข้าหน้าผู้ดูแล (ข้อความมาจากผู้เข้าชม แต่ส่งเป็นข้อความล้วน ไม่มีลิงก์/HTML ที่คลิกได้ของผู้เข้าชม)
- กันอีเมลท่วม: ถ้ามีรีวิวเข้ามาถี่ จะส่งเฉพาะฉบับแรก แล้วส่งใหม่หลังผ่านไป `'notify_min_interval'` วินาที (ค่าเริ่มต้น 300) ฉบับแรกบอกจำนวนที่รอตรวจทั้งหมด จึงตรวจที่หน้าผู้ดูแลได้เสมอ
- สมุดเยี่ยม (แสดงทันทีอยู่แล้ว) ไม่แจ้งเตือนเป็นค่าเริ่มต้น เปิดได้ด้วย `'notify_guestbook' => true`
- ถ้าส่งไม่สำเร็จ ข้อความของผู้เข้าชมยังบันทึกตามปกติ และมีบรรทัดแจ้งใน error log ของโฮสต์ (โฮสต์บางแห่งปิด `mail()` ให้ใช้ SMTP ของโฮสต์ไม่ได้ในเวอร์ชันนี้)

## CAPTCHA กันสแปม
ตั้งได้ที่ขั้นที่ 3 ของตัวช่วยติดตั้ง หรือแก้ `'captcha'` ใน config ภายหลัง (ไม่ต้องแก้หน้าเว็บ):
- **`'pow'` (ค่าเริ่มต้น):** ก่อนส่งข้อความ เบราว์เซอร์คำนวณโจทย์เล็ก ๆ เงียบ ๆ ราว 1 วินาที (เริ่มเมื่อผู้ใช้เริ่มกรอกฟอร์ม) ผู้ใช้ไม่ต้องทำอะไร ไม่ต้องสมัครบริการ ไม่ส่งข้อมูลออกนอกเว็บ ช่วยกันบอตจำนวนมากและสคริปต์ง่าย ๆ แต่ไม่ใช่การพิสูจน์ว่าเป็นคนจริง ปรับความยากด้วย `'captcha_bits'` (8-22, ค่าเริ่มต้น 16)
- **`'turnstile'`:** Cloudflare Turnstile (ฟรี) เข้มกว่า ผู้ใช้แทบไม่เห็นกล่อง สมัครที่ dash.cloudflare.com → Turnstile เพิ่มโดเมน {{HOST}} แล้วนำ Site key ไปใส่ `'turnstile_site_key'` และ Secret key ไปใส่ `'turnstile_secret'` (ต้องให้โฮสต์เปิด PHP curl หรือ `allow_url_fopen` เพื่อให้เซิร์ฟเวอร์ตรวจกับ Cloudflare) การใช้โหมดนี้ส่ง IP และข้อมูลเบราว์เซอร์ของผู้ใช้ไปยัง Cloudflare (นโยบายความเป็นส่วนตัวของเว็บระบุไว้แล้ว)
- **`'off'`:** ปิด
ถ้าผู้ใช้ส่งข้อความแล้วขึ้น "ยืนยันตัวตนไม่สำเร็จ" ซ้ำ ๆ: โหมด pow ต้องเปิดผ่าน https:// (เบราว์เซอร์ไม่ให้คำนวณบน http) ส่วน turnstile ให้ตรวจคีย์ ชื่อโดเมนที่ลงทะเบียน และ error log ของโฮสต์

## แก้ปัญหาเบื้องต้น
- **ไม่เห็นส่วนรีวิวในหน้าสถานที่:** เปิด `{{SITE}}api/reviews.php?place=sam-yot` ในเบราว์เซอร์ ควรเห็น JSON เช่น `{"place":"sam-yot","count":0,"avg":null,"items":[]}`
  - เห็น `{"error":"ระบบขัดข้อง…"}`: ตั้ง config ผิด (ไฟล์ไม่เจอ หรือรหัสผ่านฐานข้อมูลผิด) ดูข้อความละเอียดใน **error log** ของโฮสต์ (cPanel → Errors หรือไฟล์ `error_log` ในโฟลเดอร์ api)
  - เห็น 404: อัปโหลดโฟลเดอร์ `api` ไม่ครบ หรือผิดตำแหน่ง
  - เห็นโค้ด PHP ดิบ ๆ: โฮสต์ยังไม่เปิด PHP สำหรับโฟลเดอร์นี้ (เลือกเวอร์ชัน PHP ใน cPanel → Select PHP Version)
- **หน้าผู้ดูแลบอกเชื่อมต่อฐานข้อมูลไม่ได้ / ไม่มีตาราง:** ยังไม่ได้นำเข้า `schema.sql` หรือ `db_name`/`db_user`/`db_pass` ผิด (ชื่อใน cPanel มีคำนำหน้าบัญชี) หรือ `table_prefix` ไม่ตรงกับชื่อตาราง
- **ส่งรีวิวแล้วขึ้น "ส่งถี่เกินไป":** ตัวจำกัดความถี่ทำงาน (ผู้ใช้คนเดิมเขียนซ้ำเร็วเกินไป) รอแล้วลองใหม่ หรือปรับ `limits` ใน config
- **เว็บอยู่หลัง Cloudflare/CDN:** ตั้ง `'trust_proxy' => true` ใน config เพื่อให้จำกัดความถี่ตาม IP ผู้ใช้จริง (ไม่ใช่ IP ของ CDN)
- **ถ้าใช้ nginx ไม่ใช่ Apache:** ต้องตั้ง PHP-FPM (`location ~ \.php$ { fastcgi_pass …; }`) และบล็อกไฟล์ `lib.php`, `config*.php`, `places.json` ในโฟลเดอร์ `api/` ด้วยตัวเอง (nginx ไม่อ่าน `.htaccess`)
- **เพิ่มสถานที่ใหม่ในเว็บ:** ต้องสร้างชุดไฟล์ใหม่ (`npm run package -- --php …`) เพื่อให้ `api/places.json` มีรหัสสถานที่นั้น (ไม่งั้น API ปฏิเสธรีวิว)
